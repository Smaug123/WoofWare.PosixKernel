# Which union cases to reserve before WoofWare.PosixKernel 1.0

*Audit, 2026-10-10, at `origin/main` `4080652a`, in worktree `.claude/worktrees/pk-union-reserve-audit` (no commits; removed afterwards). Part of #1726, "Stabilisation". Scratch scripts are in the session's scratchpad and are not committed. No library or PawPrint code has changed.*

**The rule being applied (Patrick, 2026-10-10).** Every public union may gain a case in a minor version, except the closed list in #1845 (`SyscallAnswer`, `UnixError`, `Signal`, the flavour and numbering unions, `ProcessTermination`). Where a union is quite certain to gain a case, add the case before 1.0, unreachable until its behaviour lands. Its fields must be as certain as the case. Otherwise the later change alters a case instead of adding one, which breaks clients too.

**Result in brief.**
- 301 public F# unions. 15 hide their representation and can grow freely. Of the other 286, 9 are on the closed list and 10 are only ever built by clients, never received.
- **Reserve now:** `InodeContent.Socket` with `DirectoryEntryKind.Socket`, and `InodeContent.Fifo` with `DirectoryEntryKind.Fifo`. Also, if Patrick counts a planned device as certain, `CharacterDevice.Zero` and `CharacterDevice.Random`.
- **Reserve after a design note:** ten items, listed in §2.2. They include six shape changes to existing types that the roadmap forces. These are not new cases, but they break clients in the same way: `openat` must be able to block once FIFOs exist; a kqueue registration can name only a socket; Darwin devfs needs a mount payload and a device position; `connect` cannot block; and the public `WakeCondition.deadlines` cannot see a timerfd's setting.
- **Leave to the minor-version policy:** everything else, including `Syscall` and the `checkInvariants` defects (§2.4, §2.5).
- **A finding outside the brief (§1.1, measured).** An F# client that is not recompiled sends a new case to an *existing* arm, even if it wrote a wildcard. For a union whose cases all have no fields, it does so silently; otherwise it throws `InvalidCastException`. The compiler rejects the wildcard itself as FS0026, "rule never matched". So the README advice in #1845 does not protect such a client. Only a reserved case does, or recompiling.

## 1. Method

1. **Enumeration.** I built `WoofWare.PosixKernel` at `origin/main` and reflected over its exported types (`FSharpType.IsUnion`, with and without private access). The 301 unions and their cases are below; §A lists every one by group.
2. **Who receives each union.** A client *receives* a type if it appears in a public function's result or a public property, or inside a field or case of something it receives. A client *builds* a type if it appears in a parameter. The walk follows generic arguments, record fields and union cases. Function types flip direction for their argument. One correction is needed: a refusal passed to its own `describe` counts as "built", although the client got it from a call. With that read, 276 unions are received and 10 are only built. A new case in a union that is only built breaks no client's source: the client constructs values and never matches them.
3. **Grouping by role.** Names give the role: `*Refusal`, `*Defect`, `*Error`/`*Fault`, answers (`*Answer`, `*Outcome`, `*Admission` and the like), single-case identifiers, the closed list, and the rest. I read every union in "the rest" and every answer union by hand. The refusal, error and defect groups are decided as groups (§2.4, §2.5).
4. **Sources of "certain".** For each candidate:
   - the roadmap in #1726;
   - the options documents in this folder;
   - POSIX lists that the union plainly follows (`S_IF*` in `<sys/stat.h>`, `DT_*` in `<dirent.h>`);
   - refusal cases that already name an unmodelled feature at the point where the check has passed (`MkNodRefusal.Fifo`, `MkNodRefusal.Socket`).
   
   A case counts as certain when the roadmap plans its behaviour, or when a modelled feature implies it (FIFOs, given pipes and `mknod`). Its fields count as certain when each one is an ABI fact, a measured fact, or a design decision already taken. They are uncertain when a field would hold state whose home is undecided.
5. **Linux source.** The few kernel facts below beyond the existing documents come from Linux 6.18.7 (`/nix/store/yq0jp3zg…-linux-6.18.7.tar.xz`). Darwin facts beyond the documents are marked unmeasured.

### 1.1 What a new case does to an F# client that is not recompiled

I measured this, since the policy depends on it. Set-up: a library `v1`, a client compiled against `v1`, then `v2`'s DLL dropped in without recompiling the client. The SDK was the devshell's `net10.0`. The project files are in the session scratchpad's `bincompat/`.

| union shape in `v1` | client's match | `v2` adds | the client does |
| --- | --- | --- | --- |
| four cases, none with fields (the shape of `DirectoryEntryKind`) | one arm per case | `Fifo`, `Socket` | both run the **first** arm, silently |
| the same | the same, plus `\| _ -> "wildcard"` | the same | both run the **first** arm. The wildcard arm draws FS0026 "This rule will never be matched" and is compiled away |
| two cases with fields and one without (the shape of `ParkedSyscall`) | one arm per case, plus a wildcard | `Sleep of int64`, `Futex` | `InvalidCastException`, for both new cases (FS0026 again) |
| `A of int \| B \| C of string` | one arm per case | `D`, `E of int` | `InvalidCastException` |

Consequences:
- **#1845's README text is wrong in two places.** "A client built against an older version fails to match a new case at run time" holds only for unions with fields, and then the failure is an `InvalidCastException`, not a `MatchFailureException`. "Give each match a wildcard arm instead" cannot be written for a union the client already covers: FS0026 fires, which is an error under `TreatWarningsAsErrors` (PawPrint's setting). And the arm would not run anyway.
- **What does protect a client** is recompiling: FS0025 then names the missing case. Or a reserved case: it exists in the 1.0 build, so the client's arm for it exists too.
- **A concrete instance in PawPrint.** `NativeSystemNative.fs:3656` encodes `DirectoryEntryKind` as the PAL's `DT_*` with one arm per case. If PawPrint were built against 1.0 and run against a 1.x that adds `DirectoryEntryKind.Fifo` unreserved, it would report every FIFO as a regular file. `SignalDispatch.fs:524` covers `OpenFileTarget` in the same way, and `GuestLocation.fs` matches `ParkedSyscall` case by case.
- So reserving matters most for unions whose cases have no fields and which a client covers in full. `DirectoryEntryKind`, `CharacterDevice` and `KqueueFilter` are such unions.

### 1.2 What a reserved case costs, and how a test shows it is unreachable

- **Every complete match in the library gets an arm.** Some code treats every inode that is not a directory alike: `chmod`, `chown`, `utimensat`, `link`, `unlink`, `rename`. There, add the reserved case to the existing or-pattern; the answer will stay right when the case becomes reachable. Elsewhere (`open`, `read`, `write`, the device drivers), the arm throws, naming the reserved case and the refusal that keeps it unreachable. Each such throw is an invariant throw site in the sense of `failwith-audit-2026-10-07.md`, and the PR should count them.
- **Unreachability is a property, not a `checkInvariants` rule.** A defect case such as "reserved content present" would have to go when the behaviour lands. Removing a case is the breaking direction. So the test is a property instead: over random syscall sequences, together with `mknodat` of every `S_IFMT` value, no inode reachable from the root holds the reserved content, and no directory record reports the reserved kind. A mutation check shows the property is not vacuous: temporarily let `mknodat(S_IFIFO)` succeed, and the property fails.
- **Each reserved case gets a docstring** saying it is reserved, which call refuses to make one, and which refusal that call answers.

## 2. Verdicts

Certainty uses three words. *Certain*: the roadmap plans the behaviour, or a modelled feature implies it. *Likely*: planned "on a consumer", or post-release with no date. *Speculative*: not on the roadmap.

### 2.4 The groups decided together

- **Refusals (108).** A refusal case usually arrives with a newly measured divergence, which cannot be predicted. Refusals for planned features already exist where they are known: `SockaddrCopyRefusal.UnmodelledDomain`, `BindRefusal.UnmodelledIpv6Address`, `ConnectRefusal.Ipv6Destination`, `MkNodRefusal.Fifo`, `ClockGettimeRefusal.CpuTime`, `EpollCtlRefusal.PipeTarget`. When a feature lands, these stop being returned; they are not removed. Reserve none.
- **Errors and faults (12).** Parse and copy errors (`AbsoluteUnixPathError`, `BindFault`, `EpollCtlError`, …). Each is a decoding of a fixed input format, so it gains cases only with a newly measured rule. Reserve none.
- **Answers (50).** Each is checked above where a mode or blocking call could change it. Apart from D1 and D8, none needs a reserved case.
- **Single-case identifiers (11)** (`InodeNumber`, `SocketId`, …), and the **flavour rules and configuration** (`EmptyPathRule`, `TrailingSeparatorPolicy`, `CreationProtection`, `SimulatedPageSize`, …). A rule union has one case per measured behaviour. A third behaviour would come from a third flavour, which is a major version, or from a new measurement, which cannot be predicted. The sysctl unions already cover every value the sysctl accepts.
- **The closed list (9)** and the **15 unions with hidden representation** need nothing.

### 2.5 The `checkInvariants` defects need no reservation

The six defect unions (`UnixSystemDefect` 96, `VirtualFileSystemDefect` 17, `FileDescriptorRegistryDefect` 16, `SimulatedMachineDefect` 6, `UnixPathTextDefect` 2, `UnixByteStringDefect` 1) gain cases with every invariant. I argue they need no reserved cases:
1. **A client never branches on which invariant broke.** A defect is a bug in the library. The only right response is to stop and report it with `describe`. PawPrint matches no defect case; only the library's own tests do (119 arms, through `InternalsVisibleTo`).
2. **Their fields cannot be known in advance.** An invariant's fields are whatever the check finds, and the check belongs to a feature not yet designed.
3. **Their likely change is removal, which reservation cannot help.** When an invariant becomes a fact of the types, its case should go. PR 4 of the socket address series, for example, makes a wrong-family binding unrepresentable. Removal is the breaking direction.

So the useful pre-1.0 question is not which cases to reserve but whether these unions should expose their cases at all. The alternative is an `internal` representation: tests keep matching through `InternalsVisibleTo`, and clients get `describe`. Then adding and removing cases are both free (Q4).

## 4. Questions for Patrick

1. **§1.1:** should #1845 say "recompile against each minor version" instead of "add a wildcard arm"? An F# client that is not recompiled runs an existing arm for a new case: silently when the cases have no fields, and with `InvalidCastException` otherwise.
2. **R2:** a FIFO's open pipe stays out of `InodeContent`, as a socket inode's bound socket does. Do you agree? And since FIFOs are certain, must `openat` and `openPath` take a task and answer `SyscallOutcome` before 1.0 (D1)? The other choice is to refuse a blocking FIFO open for ever.
3. **R3:** are `/dev/zero` and `/dev/random` certain enough to reserve? Devfs D3 says "on a consumer".
4. **§2.5:** keep the defect unions public, or make their representation internal?
