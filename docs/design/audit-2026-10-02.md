# PosixKernel re-audit, 2026-10-02 (read-only, against origin/main 80b14cb9)

Ranked findings (verify against the code before acting on any):
1. epoll and kqueue are merged into CoreCLR's "socket event port" (`OpenFileTarget.SocketEventPort`, 142 `SocketEvent*` lines). kqueue has no entry point: PawPrint creates the port itself (NativeSystemNative CreateSocketEventPort, Darwin) and builds the Darwin park itself (WaitForSocketEvents → `UnixPoll.admitSocketWait`, `ParkedSyscall.SocketWait`, `UnixWait.park`). `SocketWaitAdmission` has the shim's shape; `UnixTask.MaxEvents` is documented with the shim's parameter name. Fix: (a) rename to an epoll instance and split off `OpenFileTarget.Kqueue`; (b) add `kqueue`/`kevent` entry points and delete `admitSocketWait`. Patrick asked for this on 2026-10-01.
2. Socket lengths are `int`, not `socklen_t`. A negative length makes the library failwith, citing a false shim justification. Linux answers EINVAL (from the source; unmeasured). setsockopt already takes uint32. Started 2026-10-02 (branch kernel-socklen).
3. Two conventions for copying in a pathname: most calls take a parsed `UnixPath`, and PawPrint answers EFAULT and ENAMETOOLONG itself. access, faccessat, rename and clonefile take `PathArgumentBytes`. PATH_MAX is enforced twice. Fix: every path call takes `PathArgumentBytes`.
4. open(2) flags are the client-parsed `OpenFlags` record. Its docstring is wrong about Linux: access mode 3 is accepted and unknown bits are ignored (man page; unmeasured). pipe2 and fadvise now take raw flags. Fix: raw per-flavour O_* decoding, with `OpenFlagsPal` in PawPrint. This reverses a design, so Patrick may want a say.
5. `FileStatus` holds exactly the PAL's fields: no nlink, blksize, blocks, rdev, or Darwin st_flags. PawPrint invents st_rdev 0 and UF_HIDDEN 0.
6. The named `Signal` cases are .NET's PosixSignal list (SIGKILL, SIGSTOP, SEGV, BUS, ILL, FPE and ALRM are `Other n`). There is no `sigaction` entry point; SIGKILL/SIGSTOP screening is left to the client.
7. A file is alive only while a descriptor names it. Four close refusals come from that one gap. Fix: count references to each open file, including in-flight syscalls.
8. Sockets have connection state but carry no data. The prose says "models no socket connection state". The Idle rows could be answered now. Started 2026-10-02 (branch kernel-unconnected-socket); the socket data path is Patrick's scope call.
9. On a Darwin kernel, SchedGetCpu returns a CPU number where real Darwin returns -1. Started 2026-10-02 (branch schedgetcpu-darwin).
10. Nothing checks a task's CPU against ProcessorCount, and `DOTNET_PROCESSOR_COUNT` can exceed it. Patrick decides (#742 policy).
11. Appending to `Delivered` (an ImmutableArray) is O(N²) overall. Started 2026-10-02 (branch kernel-delivered-log).
12. The kernel's state records are public, and PawPrint bypasses syscalls four times (createSocketEventPort, FileDescriptorRegistry.setNonBlocking in accept, SignalState.setDisposition, EntropyPool.draw). Encapsulation is an API policy before release: Patrick.
13. Darwin poll(2) is refused; level-triggered epoll, EPOLLONESHOT and pipe targets are refused. Patrick decides scope.
14. sockaddr decoding on the way in is left to the client. Plan stage 10 said "not proposed"; the auditor thinks that's wrong for a second client.
15. Prose that justifies a kernel decision by the shim or by managed code: Sockaddr.fs:19-26, UnixSocket.fs:403-411,1298-1308, UnixConnection.fs:513,1274, SimulatedUnixPlatform.fs:901, Inode.fs:11.
16. The README is stale ("ten syscalls"; Syscall has 29 cases).
17. fcntl exists only as O_NONBLOCK, inside UnixSocket. There is no F_GETFL access mode, F_GETFD/SETFD, F_DUPFD, or dup2/dup3.
18. GetCpuUtilization returns 0 while the kernel refuses CPU-time clocks. Patrick decides.
19. Absent: the *at calls (except faccessat), link, symlink, and device nodes (/dev/null, /dev/urandom).
20. Minor: `UnixError.toRawErrno` is partial; S_ISUID and O_NONBLOCK/O_CLOEXEC constants are duplicated.
Follow-up after stdio 6: `SignalDispatch.fs:506-516` re-implements "would a blocking read of this pipe sleep" itself.

Proposed queue: 11, 9, 8-small, 2, 3, 4, 5, 6 (two PRs), 1a, 1b, 7, 16.

Checked and rejected: a no-two-bindings-conflict invariant; `step` not covering read; the admit/write split; PawPrint's toRawErrno uses; PipeBuffer and epoll list appends (bounded); Darwin pipe2 (measured); sigprocmask (design B); "guest" in prose; "PawPrint" review markers; getRandom/getEntropy unused; FileCloneRefusal.UnmodelledFlavour; ParkedAccept.DeclaredLength; PATH_MAX on UnixPath calls.

## Decisions (Patrick, 2026-10-02)
- **#10 (task CPU above ProcessorCount):** fine for now; no change.
- **#18 (CPU time):** deferred. The .NET thread pool measures CPU, but Patrick doesn't want CPU accounting modelled in the kernel.
- **#15 (docstrings that justify by the shim):** leave the text alone. Where one is confusing, add a tag such as "OUTDATED:" to it.
- **#12 (encapsulation):** PawPrint must not bypass the syscalls or reach into kernel state. It is a client of PosixKernel with no privileged access. Where the kernel lacks the API a client needs, the kernel gains it. Plan: first remove each PawPrint bypass by adding the syscall it needs (createSocketEventPort → epoll_create/kqueue, which is #1; the FileDescriptorRegistry.setNonBlocking call in accept → the library's fcntl; SignalState.setDisposition → sigaction, which is #6; EntropyPool.draw → getrandom or a device read), then make the state records' internals `internal`, with InternalsVisibleTo the library's test project.

## Where PawPrint reaches past the syscalls (survey of origin/main fd612201, by grep)
1. **Signal dispositions.** `SignalState.setDisposition`/`disposition` are called directly by PosixSignalShim enable/disable/restore, SignalDispatch's reset-to-default, EmulatedKernel.abort (SIGABRT), StartupSignalDispositions and NativeLibc. Missing API: `sigaction` (set and return the old action) and `sigpending`.
2. **kqueue.** NativeSystemNative CreateSocketEventPort (Darwin) calls `FileDescriptorRegistry.createSocketEventPort` and writes `Process.FileDescriptors`; WaitForSocketEvents (Darwin) builds `ParkedSyscall.SocketWait` and calls `UnixWait.park`. Missing API: `kqueue()` and the wait half of `kevent()` (audit #1).
3. **Entropy.** SystemNative_GetCryptographicallySecureRandomBytes/NonCrypto and NativeRuntimeAssemblyBuilder (the MVID) call `EntropyPool.draw` and write `Machine.EntropyPool`. The library already has getrandom/getentropy. The real shim reads /dev/urandom on Linux and calls arc4random_buf on Darwin. Missing API: a /dev/urandom device node, or route through `getrandom`/`getentropy`.
4. **accept.** It clears O_NONBLOCK on the accepted fd with `FileDescriptorRegistry.setNonBlocking`, writing `Process.FileDescriptors`. The fix is to use the library's fcntl (`UnixSocket.setNonBlocking`); no new API is needed, but fcntl belongs in UnixDescriptor (audit #17).
5. **Self-pipe introspection (SignalDispatch.fs:238, 506).** Between instructions, PawPrint inspects the fd table, `PipeState.drainedBy` and `PipeBuffer.held` to decide whether the shim's signal thread would sleep in its read. After stdio 6 (#1674) this can be an actual blocking `read` parked in the kernel. Missing API: none once #1674 merges, except possibly a way to ask "would this read sleep" without doing it.
6. **The far end of stdout/stderr.** NativeSystemNative and EmulatedKernel read `Machine.Delivered` directly to see what the outside world received. Missing API: an accessor or drain for the bytes delivered to each standard-stream endpoint.
7. **Configuration.** EmulatedKernel.create applies `UnixMachineState.with*`/`UnixProcessState.with*` setters through `mapMachine`/`mapProcess`; tests do the same; the clock advances with `advanceClock`. These are library functions, not field pokes, but they can be applied at any time. Missing API: a boot configuration record passed to `UnixSystem.initial`, plus an explicit "time passes" entry point.
8. **Read-only views.** EmulatedKernel exposes nearly every Machine/Process field as a member (Sockets, Connections, NextSocketId, NextEphemeralPort, FileDescriptors, Signals, ...). Callers are unchecked; some are probably tests. These would become accessor functions, or be deleted.
Order once those exist: remove each bypass, then make the records' fields `internal` (InternalsVisibleTo WoofWare.PosixKernel.Test), which mechanically proves no client reaches in.

## Handed back to Patrick (2026-10-02): the Linux /dev/urandom descriptor
On real Linux .NET, System.Native opens its own /dev/urandom on the first call to either random entry point, so a guest's next open() lands one descriptor higher. PawPrint doesn't model this, on main or after #1687. Modelling it needs a /dev/urandom device node (finding 19), PawPrint holding the shim's descriptor, and the non-secure stream XORing lrand48 over it, which reverses #1512. Recommendation: leave it until device nodes exist, then decide.

## Decision, host configuration (orchestrator, 2026-10-02)
For the configuration setters (item 7): **B**, an unbooted phase type. `UnixSystem.initial` returns an opaque `UnixBootImage`; the existing `with*` setters take it; `UnixBootImage.boot` yields the `UnixSystem` that syscalls take, so calling a setter after boot is a compile error. `UnixMachineState.advanceClock` stays callable after boot ("time passes"). Rejected: A, a boot record taken by `initial` (the largest change to the published API, and ordering rules move inside `initial`); C, documentation only (enforces nothing). First check whether any library test changes credentials partway through a run, which would need a real `setuid(2)`. Then make the state records' fields `internal`, with InternalsVisibleTo for both test projects, or move the PawPrint tests onto queries.

## Decision, mid-run configuration found by the boot-image audit (orchestrator, 2026-10-03)
The audit found four tests that change configuration partway through a run.
- **Three of them change credentials.** All three need state created under one set of credentials and then used under another:
  - a pipe owned by someone else;
  - `/dev/null` changed to mode 0600 by root, which then drops to uid 1000;
  - `/` changed to mode 01777 by root, which then drops to uid 1000.
- **The fourth lowers `pid_max`** while tasks are alive.

**Credentials: (a).** Add the real syscalls, measured: `setresuid`, `setresgid` and `setgroups`. They are a PR of their own (`kernel-setresuid`), landed before the boot image, and the three tests drop privilege the way the probes did.
- On Linux, measure them as root and as non-root in a container: the saved-ID rules, EPERM, `-1` meaning "unchanged", and what `setgroups` needs.
- On Darwin, measure what uid 501 can do. A call that needs root is refused, typed, because it is unmeasured.
- Rejected:
  - (b), new boot-time settings for a pipe's owner, a device node's mode or the root directory's mode. Only tests want those, so they would be speculative generality.
  - (c), forging credentials on a booted system by copying records. That stops working once the fields become `internal`, and it describes no real machine.

**`pid_max`: a runtime operation, like `advanceClock`.** It is a sysctl that the outside world (root, through `/proc/sys`) can write while the machine runs. It stays callable after boot and keeps its guard against live thread IDs. Rewriting the test to boot at 400 would stop it reproducing the measured "exhaust" row.

**Setters.** The other setters are classified as the audit says: boot-time configuration moves onto `UnixBootImage`. The setters' remaining mid-run uses in tests are conveniences and move before boot.

## Decision: making the state records internal (orchestrator, 2026-10-03)
I chose the survey's option **(iii)**. PawPrint's tests move onto public queries and syscalls.
- **Rejected: (i), `InternalsVisibleTo` for `WoofWare.PawPrint.Test`.** PawPrint's tests would keep forging states its production code cannot reach. They should prove that the interpreter works through the public API.
- **The library's tests keep `InternalsVisibleTo`.** Deliberate forgeries for `checkInvariants` belong there.
- **The records made internal:** `UnixSystem`, `UnixMachineState`, `UnixProcessState` and `UnixTaskState`.
- **`UnixWait.park` and `UnixTaskTable.unpark` go internal too.** Each changes a running system without being a syscall.
- **`UnixBootImage.withEntropySeed` is accepted as boot configuration.** The pool's seed stands in for the machine's hardware randomness.

**Two stacked PRs:**
1. **PawPrint production, with no records internal yet.**
   - `EmulatedKernel` holds one `UnixSystem`, which closes the real gap: PawPrint could edit `Machine`, `Process`, `Tasks` or `Leader` directly.
   - Add the system-level read-only queries that production needs: delivered output, signals, the target of a descriptor, and so on.
   - Replace `mapMachine` with the runtime clock operation, and delete `mapTasks`.
2. **The records and the two functions above go internal, and PawPrint's tests migrate.**
   - Add the roughly 12 read-only queries the tests need.
   - Turn the PAL-conversion tests into pure tests over `ReadinessLevel`, not forged kernels.
   - Delete the forgery tests whose guards become unreachable, and turn those guards into assertions or delete them.
   - Send signals, and park and wake tasks, through syscalls.
   - If the signal or park fixtures turn out disproportionate, stop and ask. Do not fall back to (i).

## Decisions (Patrick, 2026-10-03)
- **#13 remainder.** Level-triggered epoll, EPOLLONESHOT and epoll on pipes stay refused until a client needs one. "In general, sound refusal is fine."
- **#14.** The kernel decodes `struct sockaddr` itself: bind, connect and the other address-taking calls take the caller's bytes and declared length, as path calls do, and answer the buffer-level errors (short length, unknown family) in the kernel. Options for the shape go in `sockaddr-decoding-options.md` before code.

## Decision: the epoll renames' leftovers (orchestrator, 2026-10-03)
The rename agent kept "socket event port" for names that cover epoll and kqueue alike, and left epoll's own "port" fields. Options: (a) ship the table only, and follow with a second rename PR; (b) finish the vocabulary in the same rename-only PR. Chosen: (b), since all of it is one migration (CoreLib's shim word out of the library), and a half-renamed vocabulary is two truths at once. The neutral word for "an epoll instance or a kqueue" is **event queue** (kqueue is literally the kernel event queue, and epoll's instance owns a ready list and an interest list); `EpollReadyList` stays, since `rdllist` is epoll's own term. Epoll-only "port" fields become `Epoll`, beside `ParkedKevent.Kqueue`.

## Decision: scheduling (Patrick, 2026-10-03)
The client controls scheduling, and the library provides a default. The kernel describes each decision (the tasks that could run, plus a client-supplied weight); the library offers pure policies (round-robin and PCT, moved from PawPrint's `Scheduler.fs`); the client uses them or decides itself. There are no callbacks. Interim runnable set: not parked in the kernel, minus those the client reports blocked. Long term: futex/`__psynch`. Then CPU placement and accounting (settles #10, enables #18). Tracked in #1726. Options document to follow once the current agents finish; not before the API settles.

## Decision: RLIMIT_NOFILE, handed back by the fcntl agent (orchestrator, 2026-10-03)
The library has no descriptor limit, so `dup2(fd, 2000000)` succeeds where Linux answers EBADF (the target is past any `nr_open`). That is a wrong answer, not a refusal. Options: (a) a limit in the boot image, enforced by every allocator, with `getrlimit`/`setrlimit`; (b) state the model's assumption, "RLIMIT_NOFILE is at least B", and refuse, in every allocator, a descriptor number at or above B; (c) leave it as it is. Chosen: (b) now, as its own small PR straight after kernel-fcntl; (a) later, tracked in #1726. (c) leaves a wrong answer standing. B is a per-flavour constant at or below the flavour's measured default soft limit, so every answer below it is right for any limit a process starts with. The refusal applies to `open`, `socket`, `pipe2`, `epoll_create1`, `kqueue`, `accept`, `dup`, `F_DUPFD` and the `dup2`/`dup3` targets alike, since an allocation at B is as uncertain as a dup to B.

## Decision revised: scheduling (Patrick, 2026-10-03, later)
Supersedes the decision above. The kernel stays smaller: it never chooses who runs. It answers which tasks could run, and records the client's reports of a dispatch ("task T on CPU c", checked against ProcessorCount) and of CPU time used. The default policies (round-robin, PCT) live in a separate module that knows nothing about the kernel: candidates plus client-supplied weights in, a choice out. Tracked in #1726.
